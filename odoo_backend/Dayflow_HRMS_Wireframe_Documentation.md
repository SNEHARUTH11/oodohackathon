---

### 2.2 Sign Up Page

**Route:** `/sign-up`

> ⚠️ **Note (from wireframe):** Normal users/employees **cannot self-register**. This page is used by the **HR Officer or Admin** to create new employee accounts.

#### UI Elements
| Field | Type | Notes |
|-------|------|-------|
| App/Web Logo | Image | With upload option (logo upload icon) |
| Company Name | Text Input | — |
| Name | Text Input | Employee full name |
| Email | Text Input | — |
| Phone | Text Input | — |
| Password | Password Input | Toggle show/hide |
| Confirm Password | Password Input | Toggle show/hide |
| Sign Up | Button | Primary CTA |
| "Already have an account? Sign In" | Link | Navigates to Sign In page |

#### Login ID Auto-Generation (Backend Logic)
Format: `[Company Prefix][First 2 letters of First Name][First 2 letters of Last Name][Year of Joining][Serial Number (4 digits)]`

**Example:** `OIJODO20220001`
- `OI` → Oaloo India (Company Name)
- `JO` → First 2 letters of First Name
- `DO` → First 2 letters of Last Name
- `2022` → Year of Joining
- `0001` → Serial Number for that year

> **Backend:** Login ID must be auto-generated by the system on account creation. Password is also system-generated initially. Employee logs in and can change the password afterward.

## 3. Dashboard

**Route:** `/dashboard`  
**Post-login landing page for all roles.**

### 3.1 Employee Card Grid

- Displays a **grid of employee cards** (3 columns)
- Each card shows:
  - Profile picture (avatar)
  - Employee Name
  - Status indicator icon (top-right of card)

#### Status Indicators

| Icon / Dot | Meaning |
|-----------|---------|
| 🟢 Green dot | Employee is present in the office |
| ✈️ Airplane icon | Employee is on leave |
| 🟡 Yellow dot | Employee is absent (not applied for leave, just absent) |

#### Card Click Behavior
- Clicking a card opens the **Employee Information / Profile page** in **view-only (non-editable) mode**

### 3.2 NEW Button
- Visible on the dashboard toolbar
- Opens a form to **create a new employee** (Admin/HR only)

### 3.3 Search Bar
- Filters employee cards by name in real time

### 3.4 Check In / Check Out System
Located in the dashboard (accessible to employees).

| State | UI | Behavior |
|-------|----|----------|
| Not checked in | "Check In →" button, Red status dot | On click → marks attendance, dot turns Green |
| Checked in | Shows "Since HH:MM AM/PM" + "Check Out →" button | On click → logs check-out time |

> **Backend:** Each check-in/check-out creates an **Attendance record** with employee ID, date, check-in time, check-out time.

### 3.5 Avatar Dropdown
Clicking the profile picture (avatar) in the top-right opens:
- **My Profile** → opens employee's own profile in **form/edit view**
- **Log Out** → ends session, redirects to Sign In

### 3.6 Settings (Bottom-left)
A Settings link/icon is present. See [Section 8 – Settings](#8-settings).

### 5.3 Attendance — Backend Rules

> ⚠️ **Important Notes (from wireframe):**

- On the Attendance page, employees see **day-wise attendance for the current ongoing month by default**, including break details.
- For Admins / Time Off Officers: They can see attendance of **all employees present on the current day**.
- **Attendance data serves as the basis for payslip generation.**
- The system must use attendance records to determine the **total number of payable days** per employee.
- Any **unpaid leave or missing attendance days** must automatically reduce the number of payable days during payslip computation.
- If the employee's working source is based on **assigned attendance**, the system should factor that in.

| Yearly Wage | ₹6,00,000 / Yearly |
| No. of working days in a week | (configurable) |
| Break Time | (configurable, in hrs) |

---

### 7.2 Salary Components

> ⚠️ **Important (from wireframe):** Salary components should be **calculated automatically** based on the defined Wage. The total of all components must **not exceed** the defined Wage. Values should **auto-update** when the wage amount changes.

**Computation Type:** Fixed Amount or Percentage of Wage

| Component | Example Value | % of Wage |
|-----------|--------------|-----------|
| Basic Salary | ₹25,000 / month | 50% |
| House Rent Allowance (HRA) | ₹12,500 / month | 50% of Basic |
| Standard Allowance | ₹4,167 / month | 16.67% |
| Performance Bonus | ₹2,092.50 / month | 8.33% |
| Leave Travel Allowance (LTA) | ₹2,092.50 / month | 8.33% |
| Fixed Allowance | ₹2,498 / month | 11.67% |

> Fixed Allowance = Wage − Total of all other components

---

### 7.3 Provident Fund (PF) Contribution

| Party | Amount | % |
|-------|--------|---|
| Employee PF | ₹3,000 / month | 12% of Basic |
| Employer PF | ₹3,000 / month | 12% of Basic |

---

### 7.4 Tax Deductions

| Deduction | Amount |
|-----------|--------|
| Professional Tax | ₹200 / month (deducted from Gross Salary) |

---

### 7.5 Salary Component Configuration Rules (Backend)

- **Wage Type:** Fixed Wage
- Basic = 50% of Wage
- HRA = 50% of Basic
- Standard Allowance = Fixed amount ₹4,167
- Performance Bonus = 8.33% of Basic
- LTA = 8.33% of Basic
- Fixed Allowance = Wage − (sum of all above components)
- PF rate = 12% (configurable)
- Professional Tax = ₹200 (configurable per field)

## 10. Data Models (Backend Reference)

### 10.1 User / Employee
```
User {
  id                  UUID (PK)
  login_id            String (auto-generated, unique)
  name                String
  email               String (unique)
  phone               String
  password_hash       String
  role                Enum [employee, admin, hr_officer]
  company_id          FK → Company
  department          String
  manager_id          FK → User (self-reference)
  location            String
  job_position        String
  date_of_birth       Date
  date_of_joining     Date
  gender              String
  marital_status      String
  nationality         String
  personal_email      String
  residing_address    String
  profile_picture     URL
  emp_code            String
  is_active           Boolean
  created_at          DateTime
}
```

### 10.2 Bank Details
```
BankDetail {
  id              UUID (PK)
  employee_id     FK → User
  account_number  String
  bank_name       String
  ifsc_code       String
  pan_no          String
  uan_no          String
}
```

### 10.3 Salary Structure
```
SalaryStructure {
  id                    UUID (PK)
  employee_id           FK → User
  wage_type             Enum [fixed]
  monthly_wage          Decimal
  yearly_wage           Decimal (auto = monthly × 12)
  working_days_per_week Integer
  break_time_hrs        Decimal
  basic                 Decimal (auto)
  hra                   Decimal (auto)
  standard_allowance    Decimal (auto)
  performance_bonus     Decimal (auto)
  lta                   Decimal (auto)
  fixed_allowance       Decimal (auto)
  pf_employee           Decimal (auto)
  pf_employer           Decimal (auto)
  professional_tax      Decimal
  updated_at            DateTime
}
```

### 10.4 Attendance
```
Attendance {
  id              UUID (PK)
  employee_id     FK → User
  date            Date
  check_in        DateTime
  check_out       DateTime
  work_hours      Decimal (auto-calculated)
  extra_hours     Decimal (auto-calculated)
  status          Enum [present, absent, half_day, leave]
}
```

### 10.5 Time Off Request
```
TimeOffRequest {
  id              UUID (PK)
  employee_id     FK → User
  leave_type      Enum [paid, sick, unpaid]
  start_date      Date
  end_date        Date
  days_count      Integer (auto-calculated)
  remarks         Text
  attachment_url  URL (required for sick leave)
  status          Enum [pending, approved, rejected]
  reviewed_by     FK → User (Admin/HR)
  review_comment  Text
  created_at      DateTime
  updated_at      DateTime
}
```

### 10.6 Leave Balance
```
LeaveBalance {
  id                  UUID (PK)
  employee_id         FK → User
  year                Integer
  paid_leave_total    Integer
  paid_leave_used     Integer
  sick_leave_total    Integer
  sick_leave_used     Integer
  unpaid_leave_used   Integer
}
```

### 10.7 Payslip
```
Payslip {
  id                  UUID (PK)
  employee_id         FK → User
  month               Integer (1–12)
  year                Integer
  working_days        Integer
  payable_days        Integer (from attendance)
  basic               Decimal
  hra                 Decimal
  standard_allowance  Decimal
  performance_bonus   Decimal
  lta                 Decimal
  fixed_allowance     Decimal
  gross_earnings      Decimal (auto)
  pf_deduction        Decimal
  professional_tax    Decimal
  total_deductions    Decimal (auto)
  net_pay             Decimal (auto)
  generated_at        DateTime
  status              Enum [draft, generated, sent]
}
```

### 10.8 Public Holiday
```
PublicHoliday {
  id          UUID (PK)
  company_id  FK → Company
  name        String
  date        Date
}
```

### 10.9 Company
```
Company {
  id          UUID (PK)
  name        String
  logo_url    URL
  prefix      String (2 chars, for Login ID generation)
}
```
